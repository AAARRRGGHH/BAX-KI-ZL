# BAX:KI:ZL Companion for Windows 11 (x64)

The portable application includes the current firmware for the **Waveshare
ESP32-S3-Touch-AMOLED-1.75C, SKU 33691, 32 MB flash**, plus the matching simulator.
Extract the ZIP and run `BAX-KI-ZL-Companion.exe`. No Python, ESP-IDF, Visual Studio
or installation is required on the target PC. The EXE also runs on its own.

The ZIP's `manuals` folder includes the full user manual as German and English PDFs.

The home screen uses a large logo and a combined button pair with rounded outer
ends. The logo, text, buttons and spacing scale proportionally. The client area
stays square, including while dragging any window edge or corner.

## Flash Firmware

1. Connect the Waveshare using a **USB data cable**. Close any serial monitors.
2. Choose **Flash Firmware**. The application looks for the BAX:KI:ZL CDC port or
   an Espressif USB bootloader. A ROM bootloader's USB ID is not board-specific,
   so verify that the connected board is the Waveshare model listed above.
3. Check the selected port and choose **Start Flash**. If several ports match,
   choose one explicitly. Changes in COM number during bootloader entry are
   tracked using the USB location or serial number.
4. The firmware package is checked before accessing the board. It is then written
   **directly, without an automatic backup**. Only the bootloader, partition table
   and application regions are written. NVS settings and saved slots are retained.
5. The progress bar and log show writing and verification. A success page confirms
   completion. A changed or temporarily missing CDC port does not invalidate a
   successful flash.

Keep the USB cable connected during flashing. The application cannot be closed
while the operation is active. It installs the bundled firmware only; it does
not download or compile new firmware. Use a newly built Companion package to
install a newer release.

If flashing fails, the error page provides recovery instructions. Close programs
using the COM port. For BOOT recovery, disconnect USB, hold BOOT, reconnect USB,
then release BOOT and scan again. If the device is still powered by its battery,
hold BOOT while restarting it. Flash again in BOOT mode after an interrupted write.

## Run Simulator

The complete SDL/LVGL simulator runs **inside the Companion window**, with the
original device bezel. No separate simulator window is opened. Mouse input
simulates touch and both physical buttons on the bezel are clickable. `P` is PWR;
`+` and `-` change the keyboard octave. No connected hardware is needed.

- **RESET**, shown as readable text at the top left outside the bezel, performs
  the face-down reset action. It appears only for modified chord buttons,
  resettable Arpeggiator values or existing Kinetic balls. It is hidden in
  menus, Keyboard and empty or unchanged states.
- **Right-click** opens or closes the Kinetic settings. In Keyboard and Chords,
  right-click retains its role as the second touch contact.
- To return to the Companion home screen, power off the simulated device normally:
  hold the lower bezel button or `B` for three seconds. Alternatively, close the app.

The directly launched simulator uses the same controls; powering it off exits it.
Simulator settings are saved in a persistent user folder.

## Files and logs

Files live under `%LOCALAPPDATA%\BAX-KI-ZL`:

- `logs`: flash logs and simulator diagnostics.
- `simulator`: extracted simulator, bezel, runtime libraries and simulator settings.

Choose **Open Logs** to open this folder. Backups created by older Companion
versions are left in their existing folder; new versions do not create backups.
The project's separate `Firmware.ps1 -Action Backup` command remains available
for an explicit, manual backup.

## Development and packaging

Build the desired firmware and simulator release first. Run
`Build-Companion.ps1 -InstallDependencies` once, then `Build-Companion.ps1` for
subsequent packages. This produces `dist/BAX-KI-ZL-Companion.exe` and the portable
ZIP. Packaging does not change or flash the firmware. The EXE is currently unsigned.

Source files: `launcher/app.py` (UI), `launcher/backend.py` (USB discovery, flashing
and simulator launch), `launcher/button_art.py` (antialiased outlines), and
`launcher/square_window.py` (native square resizing). The logo is rendered from
`assets/boot_logo.svg`. The simulator RESET label is generated by
`tools/build_reset_text.py` using Barlow; regenerate its mask and rebuild
after changing its typography.

The application bundles PyInstaller and esptool 4.12.0. The ZIP includes licenses
and the esptool/launcher source. Original project and library licenses still apply.

Automated checks cover device matching, package integrity, direct flashing without
backup or NVS erase, error handling, English UI diagnostics, proportional resizing,
outline rendering and persistent simulator settings. The Windows integration test
uses a real embedded SDL child window to verify reset, right-click and power-off.
A real hardware flash through this interface still requires device testing.
